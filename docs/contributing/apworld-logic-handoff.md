## Working agreements

- **Balance numbers are the user's call.** Offer two or three concrete options with their
  effect on gates and generation, recommend one, and wait for the choice.
- **Commit only when asked.** The user prefers focused commits and reviews results first.
- **Keep ascension out of logic.** This is deliberate; do not propose ascension-aware requirements.
- **Keep `logic_table.py` free of Archipelago imports.** The printer loads it on its own and a
  script test enforces that.
- **Put logic-affecting options in slot data.** Every option that changes logic must be in slot
  data and restored in `_setup_ut`, or Universal Tracker rebuilds different rules. Seeded Run
  was added for this reason.
- **Leave old logic alone.** `rules_old.py`, its relic placement in `regions.py` and its early
  items in `world.py` are deliberately independent of the table.
- **Update the design notes** whenever logic or its measured results change.

### Testing techniques that worked

- **Compare variants on identical seeds.** Run the fuzz module and patch
  `worlds.spire2.logic_table` constants before calling its `main()`. Rules read them when they
  resolve. A different option-drawing order gives different seeds, so only compare runs that
  share one.
- **Refactor equivalence.** Load the previous `rules_new.py` and `logic_table.py` from git into
  `worlds.spire2.frozen_*` modules, renaming `SpireHasPower`/`SpireHasGold` because rule names
  must be unique per game. Build two identical worlds, replace one world's rules with the frozen
  `_set_rules`, then compare every entrance result for random item counts set directly in
  `state.prog_items`. Before trusting it, mutate one frozen number to confirm it catches the
  difference.

## What to investigate next

### 1. Sparse worlds (done: `7de075b`)

Worlds with floor, gold and potion checks all off now use new logic whenever the generation has
other players, and fall back to old logic only when generated alone (user's choice, 2026-10-21,
following other worlds' use of `multiworld.players`). In new logic, their `fill_hook` orders
their own progression so fill places Card Rewards first and support last. The design notes
("Sparse worlds" and the decisions) explain why and record the measurements.

Code: `is_sparse` and `select_logic` in `rules.py`, `sparse_placement_rank` and
`SlayTheSpire2World.fill_hook` in `world.py`, the Use New Logic docstring, and
`test/sparse_fill_tests.py`. The fuzz gained `--sparse` and `--partner apquest|spire`.

**Still open, only if the user wants solo sparse worlds on new logic too:** forced solo sparse
seeds fail 8.5%; with five `useful` Card Rewards per character 2.2%, mostly Campfire Sanity
with Start of Act Ancients. Ideas not tried yet: pre-placing Rests, Smiths and Ancients before
their gates on solo generations only (as Mega Man 3's `fill_hook` pre-places a boss), or
reconsidering those gates for sparse worlds.

### 2. Shop gold per check (done: `131a468`, fuzz `29ced77`)

The user chose (2026-10-21) to require gold for the two dearest checks a shop can list, or one
with Tiered prices, counting starting and chest gold. The design notes ("Shop gold") have the
numbers, the pricing facts and why. Code: the shop gold block and functions in `logic_table.py`,
`shop_gold_by_act` and `SpireHasGold` (which now explains itself in Universal Tracker) in
`rules_new.py`, Elite/Boss Gold classification in `world.create_item`, and
`test/shop_gold_tests.py`.

Card-removal checks have no prices of their own: they borrow unused page positions and cost what
those positions cost.

Verified: 0 failures in 5000 Shop + Gold Sanity seeds with random cost modes, a Universal Tracker
rebuild test, and the full APWorld and script tests. The fuzz now draws Shop Sanity Costs too.

## Pitfalls met so far

- **Shell quirks:** the agent shell is zsh. `rm` is aliased to `rm -i` and hangs without input,
  so use `command rm -f`; `cp` is likewise `cp -i`, so use `command cp -f`. Unquoted
  `$variable` does not split into words, so use `${=variable}`.
- **Import order:** import the worlds (for example via `test.general`) before `Fill`, because
  some worlds import `Fill` while loading.
- **Edits apply immediately:** `../Archipelago/worlds/spire2` is a link to `world/spire2`.
- **Early items:** old logic has its own early items. Lowering the new Mid Act 1 power once
  shrank them by accident.
